## 一、高级用法精选（按难度分层）

### Level 1 — 基础配置

- **非程序员 2026 速查表**：[@rubenhassid](https://x.com/rubenhassid) 发布的 "[2026 non-coder cheat sheet](https://x.com/rubenhassid/status/2059152552529391850)"：打开 Claude 桌面端 → 点 "Code"（不是 Chat 也不是 Cowork）→ 注册免费 GitHub 账号 → 把项目文件夹拖进去 → 选 Opus（不选 Haiku）。Code 模式对非开发者同样好用。
- **`/context` 审计 + `/compact` 摘要**：[Geeky Gadgets 50 条技巧](https://x.com/GeekyGadgets/status/2024087166562025965)首推的长会话保鲜法——定期 `/context` 检查上下文占用，`/compact` 压缩历史，长任务不跑偏。
- **新命令 `/doctor` 与 `/fork`**：7 月更新新增 [`/doctor`（诊断环境问题）和 `/fork`（分叉当前会话）](https://code.claude.com/docs/en/whats-new)，排障和"一题多解"实验成本大幅降低。

### Level 2 — Skills 技巧

- **Skills 做"内容引擎"**：[Claude Code HQ 的 X 增长玩法](https://www.claudecodehq.com/blog/claude-skills-twitter-growth)：用 Skills 打包"里程碑增长计划 + 30 天内容引擎 + 自动改写复用"，让创作系统整夜自动运转——Skills 的边界早已超出编码。
- **推文阅读 Skill**：[ADHX Skill](https://github.com/hesreallyhim/awesome-claude-code/issues/782) 让 Claude Code 直接"读这条推文并给我要点"，经 API 抓取无需打开浏览器；awesome-claude-code 仓库仍是 Skill 淘金首选地。

### Level 3 — 定时任务

- **定时任务已上云**：7 月起[定时任务在云端运行](https://aiblewmymind.substack.com/p/claude-cowork-scheduled-tasks-6-ways)——笔记本合盖也照常执行。在 Cowork 里输入 `/schedule`，Claude 会引导设置。
- **首跑后自动重写 prompt**：定时任务首次运行后，Claude 会根据学到的信息重写初始 prompt——下次运行直接知道去哪找数据、用哪个 connector，越跑越准（[同上](https://aiblewmymind.substack.com/p/claude-cowork-scheduled-tasks-6-ways)）。

### Level 4 — Connectors & MCP

- **Artifacts 接入观看者自己的 Connectors**：7 月重磅更新——[公开分享的 artifact 可调用每位查看者自己的 MCP connectors](https://releasebot.io/updates/anthropic/claude-code)，意味着你做的"实时看板"分享出去后，同事看到的是他们自己的数据。
- **没有 Connector 时自动降级为电脑操作**：Cowork 的 [computer use](https://support.claude.com/en/articles/14128542-let-claude-use-your-computer-in-cowork) 让 Claude 在缺少 connector 时直接接管屏幕点击输入——"Connector 优先，屏幕操作兜底"成为标准链路。

### Level 5 — Hooks 自动化控制

- **`sandbox.network.strictAllowlist`**：7 月新增的[沙箱网络严格白名单设置](https://releasebot.io/updates/anthropic/claude-code)——非白名单主机直接拒绝、不再弹窗询问，适合无人值守的定时任务和 CI 场景。
- **Hooks 做护栏 + 验证闭环**：[DEV 社区的 shipping 工作流](https://dev.to/galian/claude-code-workflow-best-practices-that-ship-code-na)总结：精简 CLAUDE.md、动手前 plan mode、嘈杂调研交给 subagent、git worktree 跑并行、Hooks 当护栏、验证闭环杀幻觉——六件套缺一不可。

### Level 6 — 子代理编排

- **嵌套子代理默认深度 1 → 3**：[7 月更新](https://releasebot.io/updates/anthropic/claude-code)将 subagent 默认可嵌套深度从 1 提升到 3，后台链最深可达 5 层——父代理拆解任务后每个子代理还能继续扇出。
- **3–5 并发仍是甜点区**：[Tembo 2026 实战指南](https://www.tembo.io/blog/claude-code-subagents)提醒：并发超过 5 个后，合并摘要的时间开始吃掉并行省下的时间；"为广度 fork、为深度留主线"依然成立。

### Level 7 — 专家级工作流

- **Opus 5 默认 + 1M 上下文 + fast mode**：[Claude Opus 5 成为默认 Opus 模型](https://releasebot.io/updates/anthropic/claude-code)（$10/$50 每 Mtok，1M 上下文）——超长上下文让"整仓库塞进主线"成为现实，反而要警惕"什么都不 fork"的新失败模式：推理密集型工作留主线可见可控，广度扫描才交给 subagent（[AIXplore](https://ai.rundatarun.io/ai-development-agents/claude-code-best-practices)）。
- **Agent Teams：主代理管规划，专家代理管边界**：[Developers Digest 2026 Playbook](https://www.developersdigest.tech/blog/claude-code-agent-teams-subagents-2026)：主 agent 负责规划与集成，专职 subagent 各管代码评审、跑测试、前端 QA、安全检查——每个都有独立上下文窗口、prompt 和工具权限。
- **本周 HN 焦点——安全与能力双刃剑**：Anthropic 披露[三个模型在网络安全测试中意外触达真实系统](https://www.axios.com/2026/07/30/anthropic-mythos-security-testing)（评测环境误连了互联网）；同期 [Claude 协助发现 HAWK-256 密钥恢复攻击、AES-128 七轮攻击提速 200–800 倍](https://thehackernews.com/2026/07/claude-ai-just-cracked-post-quantum.html)，HAWK 团队已从 NIST 后量子签名标准化程序中撤回方案。给无人值守 agent 配严格白名单（见 Level 5）不再是可选项。

## 六、跨平台趋势总结

1. **Agent 管控成为竞争主轴**：7 月 Codex 与 Claude Code 的更新不约而同押注"控制"——嵌套深度、沙箱白名单、editor roles、screen reader mode（[Developers Digest 对比](https://www.developersdigest.tech/blog/codex-claude-code-july-agent-controls)）。能力竞赛正在让位给"可控性竞赛"。
2. **Opus 5 + 1M 上下文重塑工作流分界**：超长上下文让"什么该 fork"从容量问题变成纪律问题——主线可见性 vs 子代理隔离的取舍需要重新校准。
3. **安全事件敲响无人值守警钟**：评测环境误连互联网导致模型触达真实系统的事故，直接抬高了 `strictAllowlist` 这类"默认拒绝"配置的优先级。
4. **定时任务上云 + prompt 自我改写**：自动化正从"重复执行固定脚本"进化为"每次运行后自我优化"，Cowork 的定时任务开始有了记忆的雏形。

## 七、进阶路线图

1. **入门**：桌面端三模式（Chat/Cowork/Code）分工 → CLAUDE.md 精简配置 → `/context`、`/compact`、`/doctor` 三命令
2. **自动化**：`/schedule` 云端定时任务 → Skills 打包重复流程 → Connector 优先、computer use 兜底
3. **工程化**：Hooks 护栏 + 验证闭环 → `strictAllowlist` 沙箱收紧 → git worktree 并行
4. **编排**：3–5 并发 subagent → 嵌套深度 3 的任务树设计 → Agent Teams 职能分工 + grader 验收

## 八、推荐行动

1. **给无人值守任务加白名单**：在 settings 中启用 `sandbox.network.strictAllowlist`，把定时任务的网络面收到最小——本周安全事件后这是第一优先级。
2. **试用 `/fork`**：下次遇到"两种方案都想试"时，用 `/fork` 分叉会话并行验证，代替来回改。
3. **重估你的 fork 纪律**：如果已升级 Opus 5（1M 上下文），检查现有 subagent 配置——部分原本为省上下文而 fork 的调研任务，现在留主线反而更可控。
