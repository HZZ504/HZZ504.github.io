## 今日焦点

**昨天补上的这块拼图，是 Cowork 从「能干活的工具」变成「知道你是谁的同事」的分界线：Claude 聊天与 Cowork 现在共用同一份记忆。**

[@claudeai](https://x.com/claudeai) 在 8 月 25 日发布（💬253 🔁463 ❤️5,626 👁45万）的原话很克制：

> Claude 现在拥有一个跨聊天和 Claude Cowork 的记忆，你决定其中包含什么。
> 将任务交给 Cowork，它会从 Claude 已从你的聊天中了解的内容开始：你讨论过的项目、你经理的偏好，或者上季度的客户。

**这条更新真正改变的不是「记得更多」，而是「记忆发生的时机变了」。**

过去 Claude 是在**一段对话结束时**做一次总结、写进记忆。新版改成**边聊边按主题写入**——你还在对话中间，Claude 就已经把新出现的细节存进对应主题里了。这个改动看起来很小，但它是「聊天 ↔ Cowork 来回切换」能成立的前提：如果必须等对话结束才落盘，你在聊天里刚讨论完的会议安排，转手交给 Cowork 时它是不知道的。

**第二个变化是记忆从「一团文本」变成了「一张主题清单」。** 官方后续帖（💬16 🔁23 ❤️473 👁5.7万）说明：Claude 记住的一切都以**主题列表**的形式保存在「设置 → Memory」（这次 Memory 拿到了独立标签页），你可以逐条阅读、编辑或删除单个主题。截图里能看到的真实条目形态是这样的——`Meal Planning`、`Client Pitch`、`Half Marathon Training`、`Recent Work`、`Fall Offsite`、`Scope And Priorities`、`Childcare Schedule`，每条都带独立的更新时间戳。

**第三个变化是敏感话题第一次有了显式开关。** 默认不写入记忆的包括健康状况、宗教信仰、种族、性别认同等；SSN、政府证件号、犯罪记录、移民身份这类 PII 则是**任何情况下都不存**。设置里新增了一个「Include sensitive topics in memory」开关，愿意让 Claude 记住健康或信仰相关细节的用户可以自己打开。日本开发者 [@takuto_pitaliy](https://x.com/takuto_pitaliy) 的总结最简洁：「保存内容按主题单位可阅览・编辑・删除，但健康信息或宗教观等敏感话题默认不保存。」

**还有一个容易被忽略的入口：从其他 AI 提供商导入记忆。** 设置页里有 "Import memory from other AI providers"，可以把你在别家积累的上下文一次性搬过来。

**社区侧本期最值钱的资源是一个 GitHub 仓库。** [@sulekhat95](https://x.com/sulekhat95) 在 18 小时前推的 [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice)——**19.7K 星、1.7K 分叉**，README 顶栏的更新时间戳正是 `Aug 25, 2026`。它的定位不是又一份提示词合集，而是把 **Anthropic Claude Code 团队（Boris Cherny、Thariq）公开过的 84 条实操技巧**连同子代理、技能、钩子、斜杠命令、MCP、tmux + git worktrees、乃至 Claude + Codex 双模型协作工作流整合进了一套可复制的配置。仓库里被反复引用的一句话来自 Claude Code 创造者 Boris Cherny 本人：

> "There is no one correct way to use Claude Code" — 团队每个人的 setup 都不一样，你应该实验出适合自己的那套。

## 一、高级用法精选（按难度分层）

### Level 1 — 基础配置

- **今天该做的第一件事是去「设置 → Memory」通读一遍。** 记忆已经默认开启（Free / Pro / Max 全平台：web、桌面、移动端），也就是说清单里**已经有内容了**。先看它记住了什么、有没有记错，比事后发现 Cowork 按错误前提干了半小时活便宜得多。
- **把「敏感话题」开关当成一个刻意决策，而不是默认值。** 关着更安全，但也意味着「我在康复期，排程别排太满」这类真正影响 Cowork 输出质量的约束不会被记住。要么打开它，要么把这类约束写进项目指令而不是指望记忆。
- **想让某句话立刻进记忆，直接说「记住这个」。** 这是官方明确支持的显式写入方式，比指望自动抽取靠谱。
- **迁移用户先跑一次 "Import memory from other AI providers"。** 设置页里的这个入口能把其他家积累的上下文一次性带过来，省掉从零重建的几周。
- **`CLAUDE.md` 与记忆是两回事，别混用。** `CLAUDE.md` 是每轮都发送的项目级硬约定；记忆是跨对话的个人上下文，按需注入。把个人偏好塞进 `CLAUDE.md` 会白白吃掉每一轮的 token。

### Level 2 — Skills 技巧

- **记忆统一之后，skill 的写法可以更薄了。** 以前一个 `/brief` skill 往往要在开头写一大段「我是谁、我团队多大、我老板喜欢什么格式」；现在这些属于记忆的职责，skill 只需要专注**做法**本身。skill 越薄，越容易复用到别的项目。
- **反过来，别把「做法」写进记忆。** 记忆里适合放事实（项目名、人名、偏好、约束），不适合放流程（先做 A 再做 B）。流程放 skill，才有版本、能改、能分享。
- **Cowork 里最快的 skill 产出路径仍是内置 Skill Creator**：把你这周重复了三次以上的那段指令直接喂给它，让它固化成 slash command。
- **官方 marketplace 装完的 skill 一定要改写。** 通用模板产出通用结果——这是团队引入 skill 时最普遍的挫败来源。

### Level 3 — 定时任务

- **定时任务是记忆更新的最大受益者。** 一个跑了两个月的周报任务，过去每周都从同样的空白起点开始；现在它能接上你这两个月在聊天里讨论过的项目变化。相应地，**定时任务的产出质量现在依赖你的记忆卫生**——记忆里留着三个月前已经取消的项目，周报里就会一直出现它。
- **建议给每个长期定时任务配一次月度记忆体检**：打开 Memory 标签页，删掉已结束的主题。
- **[Kevin Stratvert 的 10 章教程](https://www.youtube.com/results?search_query=How+to+Use+Claude+Cowork+Step-by-Step+Tutorial+Kevin+Stratvert)（8 天前，4.2 万观看，9:42）的章节顺序依然是最好的教学设计**：本地文件 → 接 Google Drive → 更新 dashboard → **写一个可复用 skill → 跑它 → 设置周期性任务** → 用 Zapier MCP 接其他应用。先有可复用单元，再谈自动化。

### Level 4 — Connectors & MCP

- **Connector 与记忆解决的是两个不同的问题，别指望其中一个替代另一个。** Connector 给的是**实时数据**（今天的日历、这封邮件）；记忆给的是**稳定偏好**（你老板要 bullet 不要段落）。两者叠加才是 Cowork 交付物「一次到位」的实际来源。
- 推荐优先接入顺序不变：Gmail、Google Calendar、Notion、GitHub、Slack（聊天窗口左下角的加号）。
- **在写任何调用 connector 的自动化之前，先在对话里手工调一次这个工具看返回结构。** MCP wrapper 经常改名参数、重塑输出，照着 API 文档写的解析代码大概率对不上。

### Level 5 — Hooks 自动化控制

- **判断该放哪一层，仍是第一道题**：必须被强制执行的规则 → **Hooks 或 permissions**；上下文知识 → **Skills**；委派边界 → **Subagents**；始终生效的项目约定 → **`CLAUDE.md`**。
- Hooks 是生命周期上的事件脚本，本质是 AI 助手的中间件——拦截、监控、增强每一次交互（[DEV Community](https://dev.to/bredmond1019/mastering-claude-hooks-building-observable-ai-systems-part-2-2ic4)）。
- **入门顺序官方建议仍是「skill 优先」**：skill 最容易创建、见效最快；需要确定性强制时再加 hook。倒过来做的团队通常会在 hook 上卡很久。

### Level 6 — 子代理编排

- 子代理的核心价值是**独立上下文窗口**：每个子代理有自己的系统提示、自己的工具白名单、自己的上下文，彼此隔离，避免上下文污染（[Anthropic 文档](https://docs.anthropic.com/en/docs/claude-code/subagents)）。
- **[@LarryPanozzo](https://x.com/LarryPanozzo)（20 分钟前）提出的对比值得记一笔**：Codex 在等待本地运行完成时会持续消耗额度，而 **Cowork 能在子任务运行期间挂起、任务完成时再唤醒**。长时间跑测试或构建的场景，这是实打实的成本差异。
- 用 `git worktrees` + `tmux` 让多个子代理在互不冲突的工作副本上并行——这是 [claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) 仓库里最被反复推荐的一条基础设施配置。

### Level 7 — 专家级工作流

- **所有主流工作流最终收敛到同一个骨架：Research → Plan → Execute → Review → Ship。** 差别只在每一步用什么工具承载。
- **双模型协作（Claude + Codex）已经进了公开的最佳实践仓库。** 典型分工是让一个模型做实现、另一个做审查——两者的失败模式不同，交叉审查能抓出单模型自查抓不到的问题。
- **[@clementeortuzar](https://x.com/clementeortuzar)（5 小时前，💬0 🔁1 ❤️1 👁133）演示了一种轻量的跨工具交接**：把一个分析结果导出成 `.md` 文件，或通过 MCP 直接递给 Codex / Claude Code。文件是最稳的跨代理接口。
- **记忆统一之后，「专家级」的定义变了一点。** 过去的高手技巧是「怎么把上下文塞得又准又省」；现在多了一条「怎么设计一份长期正确的记忆」。前者是单次优化，后者是复利。

## 六、跨平台趋势总结

**1. 今天只有一件大事，三个平台的分工非常清楚。** X 是唯一的一手现场——官方发布 6 小时内，日本、印度、中文圈的开发者已经完成了拆解、翻译和二次传播，而且**拆解质量高于多数英文媒体报道**（[@takuto_pitaliy](https://x.com/takuto_pitaliy) 的主题级说明图比若干篇新闻稿更完整）。媒体侧（TechCrunch / The Register / 9to5Mac / SiliconANGLE / The New Stack）在同一天集中出稿，但内容高度同质。YouTube 完全没跟上——本方向最新的 Cowork 教程也是 8 天前的，尚无一条覆盖新记忆机制。**想第一时间学新功能，X 仍是唯一选择；YouTube 的价值在体系化，不在时效。**

**2. 「记忆」正在取代「上下文」成为社区的中心词。** 昨天的焦点还是 token 效率与缓存命中——那是**单次会话内**的优化。今天的焦点是跨会话、跨产品的持久记忆——这是**会话之间**的优化。两者不冲突，但注意力明显在迁移：前者的收益是线性的（每次省一点），后者是复利的（记对了一次，之后每次都受益）。

**3. 隐私叙事被官方主动前置了。** 值得注意的是，Anthropic 这次没有等媒体来问，而是在发布同时就把敏感话题清单、默认关闭策略、PII 永不存储的边界一次讲清。多家媒体的标题也顺势落在「保护敏感话题」而非「记住更多」上——这与半年前 AI 记忆功能普遍先发布后解释的节奏形成对比。

**4. 社区正在从「技巧碎片」走向「可复制配置」。** 19.7K 星的 claude-code-best-practice 之所以能起来，不是因为它收集的技巧最多，而是因为它把技巧组织成了**能直接抄的目录结构**（Agents / Commands / Skills 三分）。这与本站上期观察到的趋势一致：单条 tip 的边际价值在下降，成套配置的价值在上升。

**5. 「用哪个代理」开始变成成本问题而非能力问题。** [@LarryPanozzo](https://x.com/LarryPanozzo) 那条对比——Codex 空等烧额度、Cowork 能挂起唤醒——代表了一类新的选型依据。当各家能力趋同，**长任务的空闲计费策略**会成为真正的差异点。
