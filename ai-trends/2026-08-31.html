一、高级用法精选（按难度分层）

Level 1 — 基础配置：CLAUDE.md 是每次会话的第一份输入

CLAUDE.md 在每次会话开始时被读取，是你的常驻指令文件。适合放：项目结构约定、文件路径、代码风格、语气要求、行为护栏。

> ⚠️ 一条安全提醒（与本项目 CLAUDE.md 相关）： 网上不少教程建议把 API key 写进 CLAUDE.md。不要这么做。 该文件通常随仓库提交，密钥应走环境变量或密钥管理器。这是流传较广的一条坏建议。

Level 2 — 输出控制：Concise 输出风格 + /design

8 月的 Claude Code 加了 Concise 输出风格（结论先行，不铺垫）与 /design skill（把一个想法或一张截图变成可编辑界面）。对话冗长是最常见的 token 浪费源，Concise 是最低成本的一刀。

Level 3 — 权限即句子：auto 模式成为默认

允许 / 拒绝规则现在可以用自然语言句子写，auto 模式成为新默认。这降低了 settings.json 里手写 glob 的门槛。

Level 4 — --restricted：可以放进定时任务的"只读 Claude"

来自 2.1.248。一个 flag（等价环境变量 CLAUDE_CODE_RESTRICTED=1）一次性做四件事：

  • 移掉所有能执行命令或代码的内置工具，以及 WebFetch（除非在 --tools 里显式点名）
  • 文件工具锁死在工作目录内
  • 拒绝 bypassPermissions
  • 忽略 user / project / local 三层设置文件

最后一条是精髓：受限模式不信任仓库里的配置。处理一个不完全信任的代码库时，对方 .claude/settings.json 里写什么都不算数。


# 审阅一个来路不明的仓库：只读，不执行，不读它的配置
claude --restricted -p "总结这个仓库的架构，列出所有网络请求发起点"

Level 5 — Hooks：PreModelSwitch / PostModelSwitch

来自 2.1.251。新增两个生命周期事件，可以阻止、确认或标注一次模型切换——为受控灰度（controlled rollout）而设计。

配置结构是一棵树：顶层 hooks 键把事件名映射到匹配器数组，每个匹配器把一个 matcher 字符串配上一组 handler。团队共享的项目应放在 .claude/settings.json，让 hook 规则随仓库走、和代码一起过 review。


// .claude/settings.json —— 结构示意，字段以官方 hooks 文档为准
{
  "hooks": {
    "PreModelSwitch": [
      {
        "matcher": "*",
        "hooks": [
          { "type": "command", "command": ".claude/hooks/confirm-model-switch.sh" }
        ]
      }
    ]
  }
}

> ⚠️ 一个容易踩的坑：PreModelSwitch 上，hook 因超时被取消 = 阻止这次切换。 超时的默认行为是"拦"而不是"放"。写脚本时要保证它能快速返回，否则你会得到一个莫名其妙切不动模型的 Claude。

同版本还给 SessionStart 的 resume hook 加了两个入参：会话陈旧度（staleness） 与 预估重新缓存成本（re-cache cost）。这让"要不要恢复这个旧会话"从拍脑袋变成可判断——旧到一定程度、重建缓存贵到一定程度，就该开新会话。

完整的 30 个生命周期事件见 官方 hooks 文档。

Level 6 — 子代理编排 + 跨会话通信

跨会话消息（cross-session messaging） 落地于 2.1.248：一个会话用 ListAgents 发现你的其他会话，用 SendMessage 投递一段短文本；接收方在两次工具调用之间读取，空闲时则直接开新一轮。

  • 平台限制：macOS 与 Linux（含 WSL 2）可用，原生 Windows 不可用。 v2.1.224 及以后默认开启，无需配置。
  • 权限握手有对称规则： 每个会话用 crossSessionInbound 设置检查入站消息（accept / hold / refuse）。一个绕过权限提示的会话，会把来自"会提示"会话的每条消息扣下等你批准；反过来，一个"会提示"的接收方也会扣下来自"绕过"发送方的消息。 设计意图是不让权限级别通过消息通道被隐式提升。
  • ⚠️ 一个非直觉的关闭条件： CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC、DISABLE_TELEMETRY、DO_NOT_TRACK、DISABLE_GROWTHBOOK 中任意一个都会关掉该特性的判定，从而禁用跨会话消息。如果你在企业环境里设过这些变量，功能不生效不是 bug。

组合出的模式：--restricted 的多个 worker + 一个有权限的 foreman。 受限 worker 负责读和分析（碰不到执行工具、读不到仓库配置），foreman 汇总后执行写操作。安全边界和职责边界第一次对齐了。

Level 7 — 成本可观测：把缓存命中率变成运维指标

2.1.251 给 /cost 加了每会话的 prompt-cache 行：命中率、miss 数、重新缓存的 token 数、warm / cold 状态，并配了同构的 prompt_cache 对象供状态栏脚本读取。/usage 则加了 Spend limit 进度条，以及给网关后开发者用的 rate_limits.spend_limit 状态栏字段。

这是把"我这个月为什么花这么多"从月末对账前移到了实时状态栏。缓存命中率低通常意味着你在频繁改动 prompt 的前缀部分——那是可以重构的。

后台会话管理也补齐了： CLI help 现在包含 attach、logs、stop、respawn、rm；对一个正在运行的后台会话执行 --resume，提示里会直接给出 claude attach 的完整命令，不用再去别处查 id。

六、跨平台趋势总结

1. 一次安全修复，暴露了 agent 时代的新攻击面。

2.1.251 修了一个值得单独讲的漏洞：文件工具（Read / Write / Edit）此前会跟随一个在权限检查通过之后、被调包进工作目录的符号链接，从而在批准范围之外读写文件。这是经典的 TOCTOU（检查时/使用时） 竞态，只不过受害者从操作系统换成了 AI agent。

它的含义超出这一个 bug：当 agent 的权限模型建立在"路径"之上，而路径可以在检查后被替换，那么权限检查就是可绕过的。 这也解释了 --restricted 为什么要"忽略仓库里的配置文件"——同一个防御思路：不信任被审对象提供的任何元数据。

2. 三条产品线在同一个方向上收敛：把控制权做成可配置的边界。

  • --restricted：信任边界（这个 Claude 能碰什么）
  • crossSessionInbound 的对称握手：通信边界（哪个 Claude 能指挥哪个）
  • PreModelSwitch：变更边界（什么时候允许换模型）

8 月上半月的主题是"往外接"（内置浏览器、Claudeforce、MHS 硬件标准），下半月的主题明确转向"给接口装闸门"。这是一个功能铺开之后的正常回摆，也是企业采购真正会问的那几个问题。

3. 成本可观测性正在从"月末对账"变成"实时指标"。

/cost 的缓存命中率、/usage 的 spend limit 进度条、状态栏可读的 prompt_cache 与 rate_limits.spend_limit 字段——这套东西的受众不是个人用户，是要给团队做成本归因的人。当 token 消耗能被拆到会话粒度并暴露给脚本，它才第一次成为可以进 dashboard 的运维指标。

4. 内置浏览器的推广节奏，本机就是一个反例样本。

官方说 Pro / Max / Team 在一周内陆续到达。但本机连续两期定时任务中，内置浏览器对目标站点的导航均被拒绝——原因是无人值守的定时任务无法完成站点权限批准。这不是功能缺陷，是"默认开启的交互式浏览器"与"无人在场的定时任务"之间的结构性冲突。见第八节。

八、推荐行动

立刻做（今天）

1. 如果你在 8 月做过"9 月起 API 成本 +50%"的测算——回去改掉。 Sonnet 5 的 \$2 / \$10 已永久化，涨价取消。以 官方 Pricing 页 为准，别信任何一篇带"9 月 1 日"的旧博客。

2. 升级到 2.1.251。 它含一个符号链接调包的安全修复——文件工具此前可能在批准范围外读写。这条不是可选项。

本周做

3. 给"审阅陌生代码"这件事定一条规矩：一律 --restricted。 它忽略仓库自带配置，这正是审阅不可信代码时你需要的。

4. 跑一次 /cost 看缓存命中率。 如果命中率低，检查是不是在频繁改动 prompt 前缀——那是可重构的。

5. 写第一个 hook。 从 PostToolUse 跑 ruff format 起步，比直接上 PreModelSwitch 稳妥。记住 PreModelSwitch 超时 = 阻止切换。
