今日焦点一：/skill-doctor —— Claude Code 出了一条命令，专门告诉你哪些技能在白吃上下文

2.1.261（9/4）加了这么一行：

> "Added /skill-doctor to show which loaded skills go unused and what they cost in context, so you can prune them."

> —— Claude Code changelog 2.1.261

这条 changelog 一句话带过，但它解决的是一个大多数人根本没意识到自己在付的账。

机制是这样的：技能清单（skill listing）每一轮都会进上下文，无论 Claude 用不用它。清单预算默认是模型上下文窗口的 1%。所以一个装了却从不触发的技能，你每一轮都在为它付钱，一分钱回报都没有。

用法：

  • 交互模式：会话内敲 /skill-doctor，报告在 /plugin 管理器的 Stats 标签里打开
  • Headless：claude -p 下直接打印纯文本，可以塞进 CI

报告内容是三列：每个技能加载了没有、触发了几次、每轮吃掉多少上下文 token。

跨平台印证： 同一天 YouTube 上出现了标题就叫 「Claude Code: Find Unused Skills Before Cleanup」 的 Short（82 次观看，标记「最新」）。一条 changelog 里的小命令，48 小时内就长出了教程内容——这是判断一个功能会不会留下来的可靠信号。

今日焦点二：官方昨天（9/8）发了一篇降本长文，配了三条 /claude-api 命令 —— 附全部 benchmark 数字

Reducing cost and improving performance with Claude Platform，作者 Lance Martin，9 月 8 日发布。核心主张一句话：降本和降质不是同一件事，多数应用能在不牺牲效果的前提下砍掉一半以上开销。

三个杠杆，配三条命令。

杠杆一：提示词反模式 → /claude-api prompt-audit

官方点名了六类「给旧模型打补丁、到前沿模型上反而拖后腿」的写法：

反模式 具体写法 在前沿模型上的后果
验证仪式 "double-check your work"、"verify twice before responding" 被字面执行，每次退款都重复查一遍订单
强调助推器 "Be maximally thorough"、"CRITICAL: YOU MUST ALWAYS…" 变成几十次不必要的知识库检索
强制流程 / 草稿纸脚手架 "think step by step in a scratchpad"、固定六步流程 叠在原生推理之上，纯浪费 token
陈旧示例 针对旧模型失败模式调的 few-shot 教会新模型在简单请求上模仿长推理链
矛盾规则 "always refund within policy" vs "never refund without escalation" 指令遵循变强后，矛盾被更严格地执行，效果反降
过期配置 手动 thinking budget 等旧世代设置 直接被 Platform 拒绝请求

官方实测：Opus 4.8 → Opus 5 迁移，每次只植入一种反模式共六份提示词，跑 /claude-api prompt-audit 后平均成本降 14.6%、准确率升 5.3%。

准确率为什么会升？三个具体原因值得记：过期的 thinking 设置让 API 直接拒绝了每一个路由请求；矛盾的退款规则让 Opus 5 扣下了四笔本该退的款；手动草稿纸和 Opus 5 的内置思考撞车，三张工单里它把工具调用写进了推理，然后从没执行。

杠杆二：缓存 → 老话题，但这次给了可操作清单

上周的「Fable 5.1 烧配额」事件之后再看这段，格外具体：

  • 别在会话中途改 effort / thinking 设置 —— 它们渲染在内容之前，属于被缓存的前缀。（例外：Opus 5 和 Fable 5.1 支持会话中途改 effort 而不破缓存）
  • 前缀里别放易变值 —— 系统提示词里的动态时间戳或 ID 每次调用都在砸缓存
  • 工具定义别自己重排 —— 工具定义渲染在最顶部，任何变动都破缓存
  • 分叉要当心 —— 子代理和分支只有在前缀逐字节相同、同模型、同 effort 时才共享父级缓存
  • 别让同步工具调用/子代理跑过 TTL —— 5 分钟 TTL 从请求开始计时，超时后下一轮要按 1.25 倍价格（1 小时缓存则 2 倍）重写缓存
  • defer_loading —— 罕用工具照常声明但标记延迟加载，它们不进缓存前缀，Claude 用工具搜索找到时才追加
  • 中途系统指令走 message，不改 system prompt —— Platform 支持这么干，缓存保住
  • 压缩（compaction）时顺手换模型/effort —— 反正那一刻缓存已经要重写，是免费的换挡窗口
  • 预热缓存 —— max_tokens: 0 + 显式断点，用户还在打字时先把前缀写进缓存

杠杆三：effort 校准 → /claude-api cost-optimize 与 hillclimb

官方给的两条曲线很值得记住：

模型 / 基准 低 effort 最高 effort 结论
Fable 5 / FrontierCode Diamond（最难 50 题） 11.5%，$5.35/题 30.9%，$19.00/题 分数 ×2.7，成本 ×3.5 —— 值
Fable 5.1 / HLE（无工具） ~53%，~$0.30/题 ~61%，~$2.23/题 最后一档只加 0.5 分、成本 +46% —— 在噪声里，纯亏

也就是说 effort 的收益曲线因任务而异，「拉满总是更好」和「一律调低省钱」两边都是错的。官方原话：高 effort 会导致过度思考，「审议只在还有证据可找的时候才有用」。

/claude-api cost-optimize 在四个公开基准上的实测（都以 Sonnet 5 为基线）：

基准 降本 手段
LegalBench ~58% 跨任务缓存共享前缀 + 低 effort + Batch API；thinking token 从 102,779 降到 8,284，通过率在噪声内
tau2-bench retail ~73% 显式断点放置的提示词缓存，通过率持平
OfficeQA Pro ~52% 批处理 + 文档缓存，$136.20 → $64.87
SWE-bench Verified ~55% 缓存本来就对，省在 effort 调到 medium + 限制输出长度；中位步数 29 → 17，prompt token 75.2M → 33.7M

/claude-api hillclimb 更激进——它会把你的评测集切成训练/测试，自动搜索模型+effort+提示词组合。官方案例：从 Opus 4.8 默认高 effort 起步，最终落到 Sonnet 5 低 effort，在 14 张留出工单上得分 90.5% vs 原配置的 78.6%，成本约五分之一。

⚠️ 一个容易被忽略的用法： prompt-audit 扫的是工作目录里的一切，包括 CLAUDE.md 和你自己写的 skills。也就是说，这条命令可以直接用来审计你的 Claude Code 配置本身——不只是应用代码。

今日焦点三：2.1.265 一次性修了五个「缓存复用被打断」的 bug —— 全部集中在子代理和 agent teams

把 9/8 这一版的相关条目排在一起看，主题非常清楚：

修复 原来的行为
恢复前台派生的子代理 会改变它的工具列表和系统提示词前缀，该代理的缓存复用直接失效
agent teammates / 恢复的子代理 后续轮次会把 SubagentStart hook 上下文和预加载技能移出前缀，破缓存
进程内 agent-team teammate（2.1.261） 第二轮重发首轮的工具与技能声明，改变请求前缀，必然 miss
分叉技能（context: fork） kickoff 提示词不作为 stream-json 进度事件流出
/model opusplan[1m] 被拒："Model not found"

对照焦点二里官方那句「子代理和分支只有在前缀逐字节相同时才共享父级缓存」——这几个 bug 全都是在悄悄破坏那个「逐字节相同」。如果你重度使用子代理编排或 agent teams，2.1.265 是本周最该升的一版，它修的不是功能，是账单。

一、高级用法精选（按难度分层）

Level 1 — 基础配置

  • 先跑 /skill-doctor，再谈任何优化。 装了不用的技能每轮都在收费，这是投入产出比最高的一次清理。
  • bashOutputMaxChars / taskOutputMaxChars（2.1.261 新增） —— 把命令与后台任务的内联输出上限提到 128K 字符，超出才落盘。原来的默认值经常在长构建日志上截断关键尾部。
  • /status 与 claude doctor 现在有「Organization policy」行（2.1.261） —— 组织策略加载失败时会说明原因（比如代理没放行端点），不用再猜。

Level 2 — Skills 技巧

  • /claude-api prompt-audit 审自己的 skills。 它扫工作目录里的提示词、技能和工具描述，专挑焦点二那六类反模式。
  • 给 skills 瘦身的官方范例： claude-api 技能自己曾经加载要吃 20 万+ token，2.1.234 改成按需加载参考文档后降到约 2.5 万，初始上下文成本砍掉 85.7%。同一招适用于你自己的技能——把大段参考资料从 SKILL.md 挪到附属文件。
  • --append-subagent-system-prompt-file（2.1.261） —— 子代理系统提示词从文件读，绕开命令行长度限制。

Level 3 — 定时任务

  • 1 GB 工具结果落盘上限（2.1.265） —— 会话内预览会明确标注哪个保存的文件被截断了。无人值守任务抓大页面时，现在能知道自己拿到的是不是完整内容。
  • -p + /skill-doctor —— headless 下打印纯文本，可以把技能上下文成本做成 CI 里的一条守门检查。

Level 4 — Connectors & MCP

  • HTTP+SSE 回退修复（2.1.265） —— 配成 http 但只讲旧版 HTTP+SSE 传输的 MCP 服务器此前永远连不上，现在按 MCP 规范自动回退到 SSE。老服务器终于能用了。
  • 远程 MCP 的 OAuth 时机（2.1.265） —— Claude Code 不再在你真正认证之前就去注册 OAuth 客户端。
  • --plugin-dir 现在能指向一个「插件文件夹的文件夹」（2.1.265） —— 每个带 manifest 的子文件夹都会加载，且运行中增删子文件夹会被实时感知。本地插件开发的迭代循环从此不用重启。

Level 5 — Hooks 自动化控制

  • 注意 SubagentStart hook 与缓存的关系。 2.1.265 修的正是「hook 上下文在后续轮次被移出前缀」——升级前，你的 hook 越重，缓存被砸得越狠。
  • 危险 rm 防护增强（2.1.261） —— 现在也能抓到位置参数上的 rm -rf 和双引号 sh -c 脚本里的写法。
  • auto 模式收紧（2.1.261） —— 把内容打包进公共图表渲染器 URL 的链接，现在被视为上传到该站点，不再自动放行，除非你明确要求。

Level 6 — 子代理编排

  • 升级到 2.1.265 是前提。 见焦点三——不升级的话，你的子代理编排在缓存层面是漏的。
  • /workflows 详情增强（2.1.265） —— 工具调用会标注 running / failed / done，子代理有任务列表时会展示，Enter 展开调用的输入和结果。
  • 保证前缀逐字节一致。 官方口径：分叉共享父缓存需要同前缀、同模型、同 effort，三者缺一不可。

Level 7 — 专家级工作流

  • /claude-api hillclimb —— 给它一个评测集，它自动搜索「模型 × effort × 提示词」组合，读失败样例来指导搜索，最后在留出集上打分。官方案例把成本降到五分之一的同时提了 12 个百分点。
  • Graft（GitHub 新晋热门） —— 给代码库预先生成「概念图谱」，写成 graft/ 目录下互相链接的 Markdown，避免智能体每次重新 grep 探索。官方数据：50 题解决 33 题（Cold Claude Code 为 27 题），工具调用少 25%、token 少 23%、墙钟时间少 32%；另一组测量显示 grep token 降低 42%。支持 Claude Code / Cursor / Codex / Gemini / Copilot，graft init 一条命令接入。
  • --worktree 并行检出（2.1.265） —— 大仓库上新 worktree 现在并行 checkout（需 git 2.32+）。
