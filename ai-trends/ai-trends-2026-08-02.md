## 一、高级用法精选（按难度分层）

### Level 1 — 基础配置

- **调试黄金模板：完整代码 + 精确报错一起贴**：[@BooksByHarry](https://x.com/BooksByHarry) 分享的救命技巧——给 Claude Code 的指令里同时粘贴"当前完整代码"和"精确错误信息"，否则它会把整个流程重跑一遍浪费上下文。适合写进你的 debug 提示词模板。
- **别微观管理 AI**：Claude Code 开发者在 [Business Insider 访谈](https://x.com/farseta)中的核心建议——把任务和验收标准一次说清、附上"这些问题先自己判断"，代替逐步指挥；[@farseta](https://x.com/farseta) 转述并实践："把评论区问题丸投给 Claude，让它'答完再来'"。
- **`!` 前缀直接执行 bash + `/export` 导出会话**：r/ClaudeAI 社区 2026 高频技巧——`!` 前缀瞬时执行命令并把输出注入上下文，不浪费 token；`/export` 一键把整段会话存档（[AI Coding Daily](https://aicodingdaily.substack.com/p/claude-code-tips-and-wild-2026-predictions)）。

### Level 2 — Skills 技巧

- **给 Fable 5 搭"跨会话记忆系统"**：[@cyrilXBT](https://x.com/cyrilXBT) 的方法论文章：write（随手记）→ consolidate（归并清理）→ recall（按需检索）→ apply（真实任务中使用），四步让 agent 不再"每次开 tab 都失忆"。💬1 ❤️4 👁219
- **50+ 条实测 Skills/Plugins 技巧**：[HackerNoon 的 Cowork 长文](https://hackernoon.com/over-50-tested-tips-for-claude-cowork-everything-from-plugins-to-sub-agents-and-more)覆盖从 plugins 到 sub-agents；写 Skill 时给 3–5 个期望输出示例、说明触发时机，命中率显著提升（[Hatchworks](https://hatchworks.com/blog/claude/building-agents-with-claude/)）。

### Level 3 — 定时任务

- **Claude Code 定时任务做 GitHub 自动化**：[@Claudecode_JP](https://x.com/Claudecode_JP) 今日教程——不用 GitHub Actions，直接用 Claude Code 的 scheduled tasks 自动处理 GitHub Issues；对小团队来说少维护一套 CI 配置。
- **Cowork 定时任务是 2026 最有用特性之一**：描述一次，Cowork 自动周期执行，且可用全部 connectors/skills/plugins 组合成多步工作流（[Leadership in Change 指南](https://leadershipinchange.com/p/how-to-use-claude-cowork-task-scheduler)）。

### Level 4 — Connectors & MCP

- **文件夹即时感知是 Cowork 的差异化优势**：泰国开发者 [@rustyLAKEX](https://x.com/rustyLAKEX) 实测 Gemini Spark (beta) 对比：Spark 的 Connection Folder 看不到新落地的文件，而 Claude Cowork 对新文件"立刻可见"——connector 体验差距就在这些细节。
- **Cowork 移动版：从"回答问题"到"代替执行"**：[@kou_gb](https://x.com/kou_gb) 体验 Cowork 移动版后的总结："像在和秘书聊天，方便到指令都变得随意了"。❤️1 👁18

### Level 5 — Hooks 自动化控制

- **PostToolUse 自动格式化 + 危险命令拦截**：Meta 资深工程师 John Kim 的 50 条技巧中 Hooks 四连（Tip 47–50）：Hooks 拦截 agent 动作、PostToolUse 自动跑 formatter、显式 block 危险命令、善用插件生态（[视频见第三节](https://www.youtube.com/results?search_query=How+I+use+Claude+Code+Meta+Staff+Engineer+Tips)）。
- **CLAUDE.md 提交进 git + workflow triggers**：同一视频 Tip 20–23——Critical Rules 单独成节、让 Claude 自己更新规则、用触发词绑定工作流，团队共享一份"驯化记录"。

### Level 6 — 子代理编排

- **Subagents = 隔离上下文的专家**：John Kim Tip 39/40：子代理最大价值是独立上下文窗口，防止"指令过载"污染主线；每个 subagent 只配它需要的工具权限。
- **在 Cowork 里搭"真 Agent"而不是聊天**：[@AleiahLock](https://x.com/AleiahLock) 的 13:44 实操视频《This Is What It Looks Like to Build a Real Agent in Claude Cowork》——"大多数人打开 Claude 输入需求，拿到平庸结果就去清理，那不是 Claude 的问题，是聊天和跑 agent 的区别"。💬2 🔁2 ❤️12 👁545

### Level 7 — 专家级工作流

- **"大多数人把 Opus 5 和 Fable 5 用错了"**：[@AnatoliKopadze](https://x.com/AnatoliKopadze) 转发的 Anthropic 工程师 31:19 演讲——一个下午把模型分配设置对（什么任务用什么模型），就能"每天停止超付"；被 Cowork 圈广泛转引。
- **Claude Code 之父的 setup 已经三迭代**：[@PragatiKunwer](https://x.com/PragatiKunwer) 长文《How the Creator of Claude Code Uses Claude Code Now》——Boris Cherny 1 月公开的 setup 到 3 月已被他自己抛弃：IDE 弃用、几十个 Claude 挂循环、语音下指令；三个版本唯一不变的是"循环底层的验证习惯"。👁82
- **Fable 5 (high) 登顶 swe-rebench**：JetBrains CEO [@kskrygan](https://x.com/kskrygan) 晒出 [swe-rebench](https://swe-rebench.com) 8 月榜单：Fable 5 (high) 以 84.5% 解决率居首（$4.40/问题），Opus 5 (high) 83.4%、GPT-5.6 Sol 82.3%——选型时"每问题成本"列同样值得看。💬9 🔁3 ❤️29 👁3,966

## 六、跨平台趋势总结

1. **"先理解，后写码"成为共识**：今日 X 上 [@Alfiefps](https://x.com/Alfiefps) 的连发、Business Insider 的官方访谈、Reddit 的 Plan Mode 讨论指向同一件事——生产力瓶颈不在生成速度，在于动手前的 scope 锁定与理解深度。
2. **模型选型进入"成本纪律"阶段**：Fable 5 登顶 swe-rebench 的同时，"大多数人把 Opus 5 和 Fable 5 用错了、每天在超付"的演讲被广泛转引——按任务分配模型正成为 power user 的分水岭。
3. **Cowork 场景溢出办公室**：搬家、找保育园、企划书压缩、移动端随手差遣——日语圈今日的 Cowork 讨论几乎全是非编码场景，"AI 秘书"心智正在形成。
4. **竞品贴身战开打**：ChatGPT Work 与 Cowork 相隔 2 天发布，Gemini Spark beta 入场；实测对比中 Cowork 的文件即时感知和 connector 成熟度暂时领先，但窗口期不会太长。

## 七、进阶路线图

1. **入门**：Jeff Su 20 分钟视频分清 Chat/Cowork/Code → 调试模板（完整代码 + 精确报错）→ `!` 前缀与 `/export`
2. **自动化**：Cowork 定时任务（可组合 connectors/skills）→ Claude Code 定时任务接管 GitHub Issues → Skill 写作三要素（示例、偏好、触发时机）
3. **工程化**：Plan Mode 先行 → Hooks 四连（拦截/格式化/封禁/插件）→ CLAUDE.md 进 git
4. **编排**：Subagent 最小工具权限 → 跨会话记忆系统（write→consolidate→recall→apply）→ 按任务配模型的成本纪律

## 八、推荐行动

1. **做一次模型分配审计**：参照 Anthropic 工程师的建议，花一个下午梳理哪些任务真的需要 Fable 5/Opus 5、哪些交给 Sonnet/Haiku——"停止每天超付"。
2. **把调试模板固化成 Skill**：将"[粘贴完整当前代码] + [精确错误信息]"写成 debug skill，从此告别 Claude 重跑整个流程。
3. **给 agent 建跨会话记忆**：按 [@cyrilXBT](https://x.com/cyrilXBT) 的四步框架搭一个最小记忆系统，让每天的定时任务越跑越懂你的数据在哪。
